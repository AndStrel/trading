# Trading MCP

Безопасный MCP-сервер для анализа российских биржевых инструментов через T-Invest API.

Текущая версия получает брокерские данные, рассчитывает торговый план и может сохранить **локальную** карточку сценария. Она не умеет выставлять, изменять или отменять реальные заявки.

## Что уже есть

- два независимых профиля: `intraday` и `swing`;
- счета, портфель, позиции и остатки;
- поиск инструмента, последние биржевые цены, стакан, статус торгов и исторические свечи;
- расчёт тренда, ATR-волатильности и относительного объёма по полным свечам;
- расчёт размера позиции по риску и стоимости;
- проверка положения стопа и цели для покупки или короткой продажи;
- комиссия полного круга и ожидаемое проскальзывание;
- запрет рекомендации при `reward/risk < 2`;
- единая карточка сценария с проверкой спреда, статуса торгов, тренда и цены входа;
- локальный SQLite-журнал сохранённых сценариев без токена и сырых ответов брокера;
- paper trading: локальный вход и выход из симулированной позиции с комиссией на обе стороны и неблагоприятным проскальзыванием;
- сводка paper trading за скользящие 24 часа или 7 дней: gross/net PnL, комиссии, проскальзывание и качество выборки;
- локальный intraday-сканер: каждые 5 минут проверяет явно заданный watchlist и сохраняет только прошедшие фильтры сценарии;
- тесты, сборка и GitHub Actions.

## Локальный запуск

Требуется Node.js 22+. Токен хранится только в локальном файле `.env`; он уже исключён из Git.

```bash
git clone https://github.com/AndStrel/trading.git
cd trading
node --version
npm ci
cp .env.example .env
chmod 600 .env
```

Заполните в `.env` только `T_INVEST_TOKEN` токеном **только для чтения**. Не передавайте его в чат, issue, commit или скриншот. Затем выполните:

```bash
npm run check
npm run build
npm run smoke:tinvest
chmod 700 scripts/start-local.sh
```

Успешная проверка выведет только `T-Invest read-only authentication smoke test passed`; данные счёта и токен в вывод не попадают.

### Автоматический intraday-сканер

После настройки watchlist запустите отдельный локальный процесс:

```bash
npm run scan:intraday
```

Он не является MCP-инструментом и не зависит от открытого Inspector. Каждые 5 минут сканер берёт последние шесть часов 5-минутных свечей, стакан, последнюю цену и статус торгов. Он рассматривает только long-подход: тренд `up`, относительный объём от `1.0`, валидный ATR и действующие лимиты риска. Стоп — максимум из `1.5 ATR` и `0.1%` цены, цель — `2.5R` до издержек. При `candidate` карточка автоматически сохраняется в локальный журнал, но paper- и реальные заявки не открываются.

Для непрерывной работы через systemd см. [инструкцию сканера](docs/INTRADAY_SCANNER.md).

### Ubuntu и российские сертификаты

На 14 сентября 2026 T-Invest API отдаёт сертификат `*.tbank.ru`, выпущенный `Russian Trusted Sub CA` Минцифры. Если системный `curl` открывает `https://invest-public-api.tbank.ru/rest`, а Node сообщает `SELF_SIGNED_CERT_IN_CHAIN`, включите только в локальном `.env`:

```dotenv
T_INVEST_TRANSPORT=system-curl
```

Этот режим использует установленный в Ubuntu `curl` и его системное хранилище доверенных CA. Проверка TLS остаётся включённой: сервер не передаёт `-k`, не отключает проверку сертификата и принимает только HTTPS. Токен не передаётся в аргументах процесса: на время запроса он записывается в закрытый временный файл, который сразу удаляется.

Подключите MCP-клиент к локальному launcher — он сам найдёт `.env` рядом с проектом, поэтому токена в конфиге нет:

```json
{
  "mcpServers": {
    "trading": {
      "command": "/absolute/path/to/trading/scripts/start-local.sh"
    }
  }
}
```

После первого подключения вызовите `list_accounts`, добавьте идентификаторы счетов в локальный `.env` и перезапустите MCP:

```dotenv
T_INVEST_INTRADAY_ACCOUNT_ID=account-id
T_INVEST_SWING_ACCOUNT_ID=account-id
```

Для локальной отладки можно также запустить `npm run dev` или MCP Inspector:

```bash
npx @modelcontextprotocol/inspector scripts/start-local.sh
```

## Рабочий компьютер

На корпоративном или управляемом устройстве локальный токен потенциально доступен администраторам и защитному ПО. Для этого компьютера используйте только отдельный токен T-Invest без торговых полномочий, храните `.env` с правами `600` и отзывайте токен при смене устройства или подозрении на утечку.

## GitHub Actions

GitHub-hosted runner при проверке T-Invest вернул `SELF_SIGNED_CERT_IN_CHAIN`, поэтому он не подходит для этого токена. Рабочий MCP запускается локально, а не в Actions. Если `T_INVEST_READONLY_TOKEN` уже добавлен в GitHub Environment, удалите его после успешного локального smoke-теста и не запускайте workflow до отдельной настройки доверенной self-hosted среды.

## Границы версии 0.1

- Часть ответов T-Invest пока возвращается почти без преобразования; `analyze_candles` нормализует только свечи.
- Новостной анализ ещё не реализован. Статистика учитывает только paper-исполнения по заложенной модели; реальные брокерские исполнения не создаются и не импортируются.
- Реальные торговые команды намеренно отсутствуют.
- Это инженерный инструмент анализа, а не обещание доходности и не замена вашему подтверждению сделки.

### Локальный журнал

`record_trade_scenario` сначала собирает свежую карточку теми же проверками, что и `prepare_trade_scenario`, а затем сохраняет только входные параметры, вывод риск-расчёта, анализ свечей, оценку рынка, блокеры и предупреждения. Он не сохраняет токен и не отправляет заявку. По умолчанию журнал находится в `.trading/journal.sqlite`, папка создаётся с правами `700`, а файл базы — с правами `600`.

`list_recorded_scenarios` читает эту историю локально — без обращения к T-Invest. Это первый шаг перед paper trading: будущая бумажная сделка будет привязана к сохранённому сценарию и сможет честно учитывать комиссию и проскальзывание.

### Paper trading

`open_paper_trade` принимает только уже сохранённый сценарий со статусом `candidate` и требует `confirmPaperTrade: true`. Он получает свежую последнюю цену, моделирует худшую цену входа из-за проскальзывания и добавляет комиссию входа. Повторно открыть сделку из той же карточки нельзя.

`close_paper_trade` также требует `confirmClose: true`, получает свежую цену и моделирует неблагоприятный выход. `netPnlRub` — это результат после двух комиссий; проскальзывание уже учтено в ценах входа и выхода и не вычитается повторно. Все операции остаются только в локальном SQLite и не создают брокерских заявок.

### Отчёт paper trading

`get_paper_report` не обращается к брокеру и анализирует только закрытые бумажные сделки из локального журнала. Параметр `period` — `day` (скользящие 24 часа) или `week` (скользящие 7 дней); `endAt` позволяет построить отчёт на прошлый момент. В отчёте `grossPnlRub` уже отражает смоделированные цены исполнения, `totalCommissionRub` показывает комиссии, а `netPnlRub` — итог после них. `totalSlippageRub` приведено отдельно для прозрачности и не вычитается второй раз. При выборке менее 20 закрытых сделок MCP выдаёт предупреждение, а не делает вывод о стратегии.

### Карточка сценария

`prepare_trade_scenario` не выставляет заявку. Она блокирует сценарий при недоступной API-торговле, отсутствии лимитной заявки, ненормальном статусе торгов, неконсистентном/слишком широком стакане, нарушении лимита риска либо отключённом short. Она переводит сценарий в `review`, когда данные по тренду неполные, тренд направлен против сделки, объём низкий или цена входа заметно отличается от последней сделки.
