# Telegram-сервис и Docker

## Что запускается

Один процесс запускает intraday-сканер и Telegram-бота. Он сам проверяет watchlist раз в пять минут и присылает в Telegram только новый `candidate`. Входящий порт не открывается: бот получает команды через исходящий long polling.

Новый кандидат приходит PNG-карточкой, сформированной из сохранённого в SQLite снимка сценария. В ней есть вход, стоп, цель, объём, максимальный риск с затратами, чистый потенциал, R/R, комиссия, проскальзывание, bid/ask и 5-минутный контекст. Карточка — материал для ручного решения, не торговая заявка.

Поддерживаемые команды:

- `/status` — состояние сканера, watchlist и интервал;
- `/candidates` — до пяти последних кандидатов как PNG-карточки;
- `/preview` — тестовая PNG-карточка без запроса рынка и без записи сделки;
- `/pause` — остановить новые проходы;
- `/resume` — возобновить проходы;
- `/help` — справка.

Ни одна команда не открывает paper-сделку и не создаёт брокерскую заявку. Если PNG-карточка не отрендерилась или не отправилась, бот пишет в лог ошибку и отправляет короткий текстовый fallback, чтобы кандидат не был потерян.

## Первый запуск

1. Создайте бота в [@BotFather](https://t.me/BotFather) через `/newbot`. Токен храните только в локальном/серверном `.env`.
2. Добавьте в `.env`:

   ```dotenv
   TELEGRAM_BOT_TOKEN=полученный-токен
   TELEGRAM_ALLOWED_CHAT_IDS=
   ```

3. Запустите сервис:

   ```bash
   docker compose up --build -d
   ```

4. Откройте чат с ботом, отправьте `/start`. Он покажет ваш числовой chat ID и не даст доступа к данным.
5. Добавьте этот ID в `.env` и перезапустите контейнер:

   ```dotenv
   TELEGRAM_ALLOWED_CHAT_IDS=ваш-chat-id
   ```

   ```bash
   docker compose up -d
   ```

После этого бот начнёт принимать команды и присылать кандидатов. Сразу после развёртывания используйте `/preview`: он проверяет генерацию и доставку PNG, но все цифры в такой карточке демонстрационные. Любой другой чат получает только свой ID при `/start`; данные и управление ему недоступны.

## Перед VPS

На сервер копируются только исходники, `.env` и Docker Compose. `.env` получает права `600`, в Git он не попадает. Токен T-Invest на сервере должен быть отдельным, сначала — только для чтения.

Образ сервиса устанавливает корневой и промежуточный сертификаты НУЦ Минцифры с официального источника и запускает Node с системным хранилищем CA. В образ также входит `librsvg2-bin`, который рендерит карточки на временную файловую систему контейнера; PNG не сохраняются на диске. Контейнер остаётся read-only, а `/tmp` — отдельный `tmpfs` с обычными безопасными правами `1777`, `noexec` и `nosuid`. CI запускает реальный PNG-рендер в контейнере с этими же ограничениями.

Оставьте в `.env` стандартное значение:

```dotenv
T_INVEST_TRANSPORT=fetch
```

После deploy проверьте TLS **из контейнера**:

```bash
docker compose exec telegram-service curl -sS -o /dev/null -w 'HTTP %{http_code}\n' \
  --connect-timeout 10 https://invest-public-api.tbank.ru/rest
```

`HTTP 404` здесь означает успешное TLS-соединение с базовым REST-маршрутом. Запрещены `curl -k`, `NODE_TLS_REJECT_UNAUTHORIZED=0` и любые отключения проверки сертификата.

Если `/preview` прислал текст «Карточка не сформировалась», откройте последние сообщения сервиса:

```bash
docker compose logs --tail=50 telegram-service
```

В рабочем образе команда `npm run smoke:candidate-card` должна завершаться строкой `Candidate card render smoke passed`. Этот тест не обращается к Telegram, T-Invest или сети.

Контейнер намеренно не публикует порты и хранит SQLite в Docker volume. Перед переходом на сервер нужно отдельно настроить резервное копирование этого volume и проверить восстановление.

## Операционные команды

```bash
docker compose logs -f
docker compose ps
docker compose restart
docker compose down
```

`docker compose down` не удаляет журнал. Команда `docker compose down -v` удалит Docker volume с историей — её использовать нельзя без проверенной резервной копии.
