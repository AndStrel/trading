# Исследовательский каталог ситуаций

## Что добавлено

`history:import` хранит исходные минутные свечи и provenance архива. `research:catalog` строит поверх них компактный research-only каталог:

- признаки считаются только по свечам, доступным на `featureAvailableAt`;
- будущие значения лежат отдельно в `research_outcomes` и не попадают в `featureVector`;
- каждая запись связана с тикером, инструментом, годом и SHA-256 исходного архива;
- повторная сборка одного инструмента и года заменяет только его каталог, не создавая дублей;
- поиск похожих ситуаций ограничивает и время признаков, и время завершения каждого возвращаемого исхода.

Production scanner, execution path и paper-trading контур этот каталог не используют.

## Шаг 1. Скачать историю

Для публичного MOEX токен и `.env` не нужны:

```bash
npm run build
node dist/history-import.js --source moex --year 2023,2024,2025 --ticker SBER,GAZP
node dist/research-catalog.js --year 2023,2024,2025 --ticker SBER,GAZP
```

Для T-Invest — на машине с настроенным `.env` и read-only `T_INVEST_TOKEN`:

```bash
npm run build
npm run history:import -- \
  --year 2023 --year 2024 --year 2025 \
  --ticker SBER,SBERP,GAZP,LKOH,ROSN,NVTK,TATN,TATNP,SNGS,SNGSP,GMKN,PLZL,CHMF,NLMK,MTSS,MGNT,MOEX,AFLT,ALRS,HYDR
```

Импорт последовательный и может занять заметное время. Перед массовым запуском проверьте свободное место: база хранит все минутные свечи отдельно от журнала.

Если полный список пока слишком тяжёлый, первый технический прогон:

```bash
npm run history:import -- --year 2023 --year 2024 --year 2025 --ticker SBER,GAZP
```

`--source auto` используется по умолчанию: T-Invest остаётся быстрым основным источником, а при сетевой недоступности импорт продолжится через MOEX ISS. Источник каждого годового набора фиксируется в SQLite provenance и JSON-логе.

Если источник содержит невалидные или повторные строки, импорт сохраняет разобранные свечи для диагностики, но завершается ошибкой. `partial` не означает готовность данных; каталог такой набор не принимает. Нельзя автоматически исправлять объёмы или исключать дни по результату стратегии.

## Запуск через GitHub Actions

Если нет доступа к домашнему компьютеру или VPS, после merge PR с этим workflow откройте:

`GitHub → Actions → Research historical dataset → Run workflow → Branch: main`.

Для первого запуска оставьте значения по умолчанию:

```text
years: 2023,2024,2025
tickers: SBER,GAZP
lookback_minutes: 30
step_minutes: 5
outcome_minutes: 15,30,60
min_free_gb: 4
```

Workflow использует только уже настроенный Environment `production`, secrets SSH и серверный read-only `.env`. Он блокируется общей группой `trading-telegram-production`, проверяет SSH host key и свободное место, собирает образ, запускает одноразовые контейнеры с `--no-deps` и не перезапускает Telegram-сервис. Перед импортом оба адреса T-Invest проверяются без токена: если недоступны оба, workflow сразу выбирает `--source moex`, а не ждёт длинную цепочку бесполезных retry. Логи импорта/каталога сохраняются в artifact `research-dataset-<run_id>`.

После успешного прогона пришлите ссылку на run или его artifact — по нему проверим фактическое покрытие, число ситуаций и ошибки по инструментам.

## Шаг 2. Построить каталог

```bash
npm run research:catalog -- \
  --year 2023 --year 2024 --year 2025 \
  --ticker SBER,GAZP \
  --lookback-minutes 30 \
  --step-minutes 5 \
  --outcome-minutes 15,30,60
```

Команда выводит JSON по каждому архиву: источник, хеш, число свечей, ошибки, покрытие по месяцам и московским датам, разрывы внутри дня отдельно от ночных и число ситуаций. Отсутствующий запрошенный тикер/год, несколько источников одного набора, ошибки/дубли строк и пропущенные месяцы приводят к ненулевому завершению. Полный год требуется намеренно; этот этап не предназначен для незавершённых лет.

`calendarValidated: false` означает, что даже успешно построенный каталог НЕ доказывает полноту торговых сессий. Внутридневные разрывы могут быть перерывами или отсутствием сделок. Следующий допуск требует сверки с историческим календарём; нельзя считать все такие разрывы ошибками поставщика.

Схема `situation-v2` сейчас содержит десять нормализованных признаков: доходности за 1/5/15/30 минут, диапазон, реализованную волатильность, отношение объёма, положение закрытия в диапазоне, drawdown и runup. Масштабирование признаков зафиксировано в коде и не подбирается по будущему периоду.

Миграция: пересоберите каталог из исходных свечей. `situation-v1` остаётся в базе для аудита, но CLI больше её не ищет. `observedAt` — начало свечи, `featureAvailableAt` — начало следующей минуты (закрытие исходной свечи). `terminalAt` — момент доступности закрытия конечной свечи, а не её начало.

## Шаг 3. Найти похожие прошлые ситуации

Сначала возьмите точный timestamp из вывода каталога, затем выполните:

```bash
npm run research:similar -- \
  --ticker SBER \
  --at 2025-06-03T08:30:00.000Z \
  --neighbors 20
```

`--at` выбирает свечу; фактический cutoff — её `featureAvailableAt` (+1 минута). Соседи имеют строго более ранние признаки, а возвращаемые исходы — `terminalAt <= cutoff`. У недавнего соседа исходов может не быть: это неизвестность, а не нулевая доходность. Исход целевой ситуации в CLI не выводится. Соседство пока является детерминированным Euclidean baseline, не сигналом на покупку.

## Что дальше для RAG и embeddings

Следующий слой — отдельный индекс документов и событий: отчёты экспериментов, описания гипотез, quality reports и агрегаты по кластерам ситуаций. Текстовые документы нельзя смешивать с минутными свечами: свечи ищутся числовым вектором, а RAG подтягивает объяснение и доказательства.

Перед подключением конкретной embedding-модели нужно зафиксировать модель, размерность, версию признаков и train/OOS split. До этого не следует считать cosine similarity модельных векторов подтверждением стратегии: сначала baseline должен показать устойчивый результат на временном out-of-sample периоде.

## Ограничения текущей версии

- календарь торговых дней и праздников пока не является частью каталога; разрывы минутных свечей не пересекаются, но качество торговых сессий надо валидировать отдельным этапом;
- каталог не является сигналом и не подключён к live execution;
- forward-outcomes описывают цену/диапазон OHLCV, а не реальные bid/ask fills;
- точная глубина архива зависит от инструмента и доступности годового архива у T-Invest, поэтому перед исследованием нужно проверить фактический coverage в JSON-логе.
