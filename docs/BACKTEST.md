# Replay/backtest исторических данных

`backtest:replay` — это воспроизводимая проверка одного **зафиксированного** intraday-плейбука на архивных минутных свечах T-Invest. Команда не обращается к текущему списку `Shares`: тикер, UID, лот и шаг цены берутся из provenance, сохранённого вместе с годовым архивом. Поэтому replay остаётся доступен для делистнутой или заблокированной сегодня бумаги и не меняется из-за последующих изменений API. Она не создаёт ни sandbox-, ни реальных заявок.

## Что именно проверяется

Первая версия называется `vwap-pullback-v1` и намеренно не подбирает параметры по результату:

1. Работа только long, без плеча и максимум с двумя одновременно открытыми позициями.
2. На закрытой 5-минутной свече нужен тренд: `SMA20` минимум на 0,2% выше `SMA50`, достаточный средний оборот и relative volume не ниже 1.0.
3. Relative volume текущей 5-минутки сравнивается только с тем же временем дня за **20 предыдущих завершённых сессий**. Данные текущего или будущих дней в базу сравнения не попадают.
4. Нужны касание session VWAP предыдущей свечой и возврат выше VWAP на текущей свече.
5. Сигнал появляется после закрытия 5-минутки, а вход моделируется только по `open` **следующей** минутной свечи. Так цена, которой сформирован сигнал, не используется как цена входа.
6. Стоп — максимум из `1.5 × ATR14` и 0,1% входа; цель гарантирует не менее 2R после модельных издержек с запасом двух ценовых шагов.
7. Если в одной минутной OHLC-свече были достигнуты и стоп, и цель, replay считает, что сначала сработал стоп. Это намеренно неблагоприятное допущение.
8. Позиция закрывается по стопу, цели, через 90 минут или не позже 18:40 МСК. Одна бумага — не более одной исполненной позиции за сессию.
9. При пропуске минутной свечи открытая позиция закрывается по `open` первой следующей наблюдаемой свечи с обычным неблагоприятным проскальзыванием; предыдущая цена задним числом не используется.

Из вечерней сессии данные в индикаторы этой версии не попадают. Это не «лучшая стратегия», а первый заранее описанный baseline, на котором можно честно проверить логику расходов и отсутствие lookahead.

## Зафиксированное разбиение 2025

Для `--year 2025` границы заданы в коде до просмотра результатов:

| Период | Даты МСК | Назначение |
|---|---:|---|
| Warm-up | январь–март | только прогрев SMA/relative volume, не оценивается |
| Development | 1 апреля – 31 августа | первичная проверка фиксированного baseline |
| Validation | 1 сентября – 31 октября | проверка без смены правил |
| Out-of-sample | 1 ноября – 31 декабря | отложенная, неиспользованная при настройке часть |

После просмотра OOS нельзя менять правила и снова называть тот же ноябрь–декабрь «отложенным периодом». Любой следующий вариант стратегии получает новую версию и новый будущий holdout.

## Издержки и капитал

Модель берёт фактические настройки сервиса:

```dotenv
T_INVEST_COMMISSION_RATE=0.0005
T_INVEST_SCANNER_SLIPPAGE_RATE=0.0005
T_INVEST_BACKTEST_STARTING_CAPITAL_RUB=100000
T_INVEST_BACKTEST_MAX_CONCURRENT_POSITIONS=2
INTRADAY_MAX_RISK_RUB=500
INTRADAY_MAX_POSITION_RUB=50000
```

`0.0005` означает 0,05% за одну сторону. На входе модель ухудшает цену на slippage и удерживает комиссию; на выходе снова ухудшает цену и удерживает комиссию. Поэтому:

```text
net PnL = raw market PnL − entry/exit slippage − entry/exit commission
```

Капитал cash-only: новая позиция не открывается, если после уже зарезервированных сделок не хватает денег, либо достигнут лимит одновременно открытых позиций. При равных сигналах в одну минуту порядок определяется тикером, а не будущим результатом.

В отчёте отдельно видны `marketPnlRub`, `pnlAfterSlippageRub`, `totalSlippageRub`, `totalCommissionRub` и `netPnlRub`. Все денежные списания округляются до копеек, поэтому итоговый капитал сверяется с журналом сделок.

## Запуск после импорта

Сначала должны быть загружены **все** 20 архивов за год. По умолчанию используются:

```text
SBER, SBERP, GAZP, LKOH, ROSN, NVTK, TATN, TATNP, SNGS, SNGSP,
GMKN, PLZL, CHMF, NLMK, MTSS, MGNT, MOEX, AFLT, ALRS, HYDR
```

```bash
npm run build
npm run backtest:replay -- --year 2025
```

Для изолированного исследования можно передать подмножество; это не сопоставимо с результатом `liquid-20`:

```bash
npm run backtest:replay -- --year 2025 --ticker SBER,GAZP
```

Команда принимает только завершённый календарный год и завершится ошибкой, а не выкинет молча тикер, если для хотя бы одной запрошенной бумаги отсутствует подтверждённый импорт данного года, сохранённый тикер/UID или метаданные лота и шага цены. JSON-вывод содержит полный audit-ledger сделок, SHA-256 каждого использованного архива, сохранённые метаданные и полный нормализованный набор параметров replay — без токенов и номеров счетов.

## Как читать результат

- Смотрите прежде всего `out_of_sample`, а не лучший период development.
- `profitFactor`, win rate и доходность бессмысленны как вывод при малой выборке; при менее 30 OOS-сделках команда прямо выдаёт предупреждение.
- `realizedMaxDrawdownRub` строится по последовательности закрытых сделок. Это не внутрисвечная и не mark-to-market просадка, поэтому он не заменяет стресс-тест.
- Результат archive-OHLCV не знает реальный bid/ask, частичное исполнение и фактическую очередь в стакане. Slippage — намеренно неблагоприятная модель, не измеренная реальная величина.

В модели пока нет НДФЛ, платы за перенос позиции, займа бумаг, корпоративных действий и индивидуальных скидок/изменений тарифа. Для long-only внутри дня часть из них обычно неприменима, но их нельзя считать нулевыми без сверки с реальным брокерским отчётом.

Положительный backtest не является обещанием прибыли и не является допуском к реальному счёту. Следующие обязательные шаги после результата: независимый бумажный прогон, сверка модели со сделками sandbox и новые OOS-периоды.
