плановая прибыль не результат; sandbox не live; страна IP не доступность API;

Состояния приёмки: загрузка, обновление, пустой список, отсутствующие/устаревшие
данные, ошибка соединения, pending, disabled с причиной, подтверждение,
истёкшая авторизация, конфликт версии, неизвестный исход мутации без автоповтора.

## Синхронизация с функциональными PR

Перед стартом, после базового внедрения и перед публикацией проверяются свежие
`origin/main` и открытые PR. Уже merged commits включаются в дизайн-ветку.
Незамерженный PR не вливается автоматически: сначала читается diff/проверки,
определяется влияние на UI контракт. Функциональные checkout не изменяются.
На старте открыт #74 (sandbox native-stop acceptance); #78/#79 уже в базе.

## Выкатка и откат

Этот этап создаёт отдельный PR, не деплоит сервис, не включает торговлю и
не меняет брокерские/Telegram-секреты. После согласованного merge/deploy
проверяются настоящая Telegram-загрузка и обе темы; локальный браузер не
доказывает работу клиентского safe-area на каждом телефоне.
Откат — восстановить предыдущие статические assets/image без изменения журнала,
секретов, лимитов или исполнительного контура.
