# Безопасность

## Сейчас

- сервер работает только через локальный `stdio`;
- токен читается из локального `.env` и не выводится;
- `.env` исключён из Git;
- MCP и сканер используют только read-only методы; отдельный executor умеет отправлять подтверждённые заявки исключительно в песочницу T-Invest;
- счета выбираются через фиксированные роли;
- `record_trade_scenario`, `open_paper_trade` и `close_paper_trade` меняют только локальный SQLite-журнал, а не брокерский счёт;
- вход и выход paper trade требуют отдельного явного подтверждения в параметрах инструмента;
- журнал хранится в исключённой из Git папке `.trading/` с правами папки `700` и базы `600`; токен и сырые ответы API в него не записываются;
- исторические минутные свечи хранятся в отдельной локальной SQLite-базе без токена и ZIP-архивов; у импортов сохраняется только контрольная сумма и техническая статистика;
- сетевой запрос ограничен таймаутом 10 секунд.

## Правила эксплуатации

1. Создавать отдельный токен T-Invest только для чтения для MCP и сканера.
2. Хранить его в локальном `.env` или хранилище секретов.
3. На macOS/Linux установить права `600` на `.env`.
4. Никогда не передавать `.env` в AI-контекст.
5. Для sandbox-executor использовать второй токен с торговыми полномочиями в `T_INVEST_TRADING_TOKEN`; не переиспользовать его как `T_INVEST_TOKEN`.
6. Не включать маржинальную торговлю и короткие позиции на первых этапах.
7. Отзывать токен при подозрении на утечку или смене устройства.

На корпоративном или управляемом компьютере к локальным файлам могут иметь доступ администраторы и защитное ПО. Используйте на нём только отдельный read-only токен, не токен с торговыми правами.

## Российские сертификаты и system-curl

- По умолчанию используется встроенный `fetch` Node.js.
- Режим `T_INVEST_TRANSPORT=system-curl` предназначен только для Ubuntu, где Node не принимает цепочку Минцифры, но системный `curl` её проверяет.
- `system-curl` не отключает TLS-проверку, не использует `-k` и разрешает только HTTPS.
- Токен не передаётся через аргументы `curl`. Для заголовков создаётся файл с правами `600` в закрытой временной директории; он удаляется сразу после каждого запроса.
- При скачивании годового архива `system-curl` также записывает тело ответа только во временный файл с правами `600` и удаляет его после чтения.
- Не устанавливайте в проект непроверенные CA-файлы из сторонних источников.

## GitHub Actions

- В GitHub-hosted runner запрос к T-Invest завершился ошибкой `SELF_SIGNED_CERT_IN_CHAIN`.
- Поэтому workflow не является рабочим путём проверки этого токена и не должен запускаться с брокерским секретом.
- Если `T_INVEST_READONLY_TOKEN` уже создан в Environment `tinvest-readonly`, удалите его после успешной локальной проверки.
- GitHub Actions не является средой исполнения торгового MCP и не хранит рабочий токен локального сервера.

## Paper trading

- Paper trade не использует метод выставления заявки и не передаёт в T-Invest команду на покупку, продажу, отмену или изменение заявки.
- Единственный рыночный запрос при входе и выходе — read-only последняя цена.
- `get_paper_report` читает только локальную базу и не делает сетевых запросов.
- `scan:intraday` делает только read-запросы T-Invest; он не вызывает методов заявок и не открывает даже paper-позиции.
- Watchlist берётся только из локального `.env`; по умолчанию он пуст, поэтому сканер не может начать наблюдение за случайным инструментом.
- Модель применяет неблагоприятное проскальзывание к цене исполнения и удерживает комиссию за обе стороны; это симуляция, не обещание соответствия фактическому исполнению.

## Sandbox execution

- Реальный endpoint `OrdersService/PostOrder` отсутствует; клиент допускает только `SandboxService/PostSandboxOrder`.
- Каждая заявка требует `/approve ID CONFIRM` из allowlisted Telegram-чата.
- После первого запуска kill switch включён. `/execution_arm SANDBOX` создаёт и пополняет отдельный виртуальный счёт, затем разрешает подтверждения; `/kill` снова блокирует отправку.
- Разрешены только long, лимитная цена из детерминированной карточки, `TIME_IN_FORCE_FILL_OR_KILL` и `confirmMarginTrade=false`.
- Перед отправкой повторно проверяются возраст кандидата, нормальный статус торгов, API-доступность лимитной заявки, текущий спред, отклонение цены и объём лучшего ask.
- Одна карточка имеет один стабильный UUID запроса. После сетевой неопределённости повтор использует тот же UUID.
- SQLite хранит текущее состояние поручения и append-only события аудита без токенов. Действуют лимиты числа заявок и суммарного расчётного риска за московский календарный день.
- `/kill` запрещает новые запросы, но не закрывает уже исполненную виртуальную позицию.

## До реальной торговли

Sandbox закрывает требования отдельного токена, подтверждения, allowlist, лимитов позиции/сделки/дня, запрета рыночных заявок, idempotency, аудита и kill switch. До реального счёта остаются обязательными: защитные выходы, reconciliation заявок и сделок, расчёт фактического дневного PnL/лимита убытка, sandbox-приёмка и ограниченный пилот.
