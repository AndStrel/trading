# Telegram-сервис и Docker

## Что запускается

Один процесс запускает intraday-сканер и Telegram-бота. В обычном режиме сканер сам обновляет через T-Invest API рабочую вселенную ликвидных акций Мосбиржи и раз в пять минут ранжирует их. В Telegram он присылает только новый `candidate`; команда `/market` объясняет, сколько инструментов прошло каждый фильтр и показывает лучшие ситуации, даже когда кандидатов нет. Входящий порт не открывается: бот получает команды через исходящий long polling.

Новый кандидат приходит PNG-карточкой, сформированной из сохранённого в SQLite снимка сценария. В ней есть вход, стоп, цель, объём, максимальный риск с затратами, чистый потенциал, R/R, комиссия, проскальзывание, bid/ask и 5-минутный контекст. Под карточкой появляются кнопки подтверждения и отклонения; сама карточка ещё не является брокерской заявкой.

Поддерживаемые команды:

- `/status` — состояние сканера, вселенная и интервал;
- `/market` — последний проход: размер вселенной, ликвидность, тренд, объём, кандидаты и топ-5 ситуаций;
- `/candidates` — до пяти последних кандидатов как PNG-карточки;
- `/preview` — тестовая PNG-карточка без запроса рынка и без записи сделки;
- `/pause` — остановить новые проходы;
- `/resume` — возобновить проходы;
- `/execution` — режим, готовность sandbox-счёта и kill switch;
- `/pilot` — read-only проверка дневного профиля; никогда не разрешает live-отправку;
- `/orders` — пять последних подготовленных sandbox-поручений;
- `/execution_arm SANDBOX` — проверить отдельно подготовленный sandbox-счёт и разрешить подтверждённые заявки; не создаёт и не пополняет счёт;
- `/approve ID CONFIRM` — подтвердить одну свежую sandbox-заявку;
- `/reject ID` — отклонить подготовленную sandbox-заявку;
- `/kill` — запретить новые отправки заявок;
- `/help` — справка.

Реальный торговый счёт недоступен. В режиме `sandbox` бот готовит поручение автоматически, но отправляет его только после точной команды `/approve ID CONFIRM`. Используется лимитная FOK-заявка: без маржи, без short и без остающейся на ночь заявки. Если PNG-карточка не отрендерилась или не отправилась, бот пишет в лог ошибку и отправляет короткий текстовый fallback, чтобы кандидат не был потерян.

## Первый запуск

1. Создайте бота в [@BotFather](https://t.me/BotFather) через `/newbot`. Токен храните только в локальном/серверном `.env`.
2. Добавьте в `.env`:

   ```dotenv
   TELEGRAM_BOT_TOKEN=полученный-токен
   TELEGRAM_ALLOWED_CHAT_IDS=
   ```

3. Запустите сервис:

   ```bash
   docker compose up --build -d
   ```

4. Откройте чат с ботом, отправьте `/start`. Он покажет ваш числовой chat ID и не даст доступа к данным.
5. Добавьте этот ID в `.env` и перезапустите контейнер:

   ```dotenv
   TELEGRAM_ALLOWED_CHAT_IDS=ваш-chat-id
   ```

   ```bash
   docker compose up -d
   ```

После этого бот начнёт принимать команды и присылать кандидатов. Сразу после развёртывания используйте `/preview`: он проверяет генерацию и доставку PNG, но все цифры в такой карточке демонстрационные. Любой другой чат получает только свой ID при `/start`; данные и управление ему недоступны.

## Включение песочницы

1. Используйте выделенный токен песочницы. `T_INVEST_TOKEN` оставьте отдельным токеном только для чтения; существующий production-токен не назначайте одновременно песочнице.
2. Добавьте на сервер в `.env`:

   ```dotenv
   T_INVEST_EXECUTION_MODE=sandbox
   T_INVEST_SANDBOX_TOKEN=выделенный-токен-песочницы
   T_INVEST_TRADING_TOKEN_ROLE=live
   T_INVEST_SANDBOX_ACCOUNT_ID=
   T_INVEST_SANDBOX_INITIAL_BALANCE_RUB=1000
   T_INVEST_EXECUTION_MAX_ORDERS_PER_DAY=3
   T_INVEST_EXECUTION_MAX_DAILY_RISK_RUB=60
   T_INVEST_EXECUTION_CANDIDATE_MAX_AGE_MINUTES=10
   ```

3. Перезапустите контейнер и отправьте боту `/execution`. Ожидается: режим `sandbox`, токен задан, kill switch включён.
4. Только после отдельной подтверждённой подготовки отправьте `/execution_arm SANDBOX`. Бот проверит её приватную запись и свежие данные счёта; создание и пополнение этой командой запрещены. Нужны пустые позиции/книги и начальный RUB-остаток из конфигурации (для пилота — 1 000 ₽). Старый ID или отметка о пополнении не заменяют доказательство подготовки. Пока исход предыдущего запроса неизвестен, активация запрещена. Идентификатор счёта остаётся только в локальном SQLite.
5. Новый кандидат будет содержать кнопки `Подтвердить sandbox` и `Отклонить`. Перед нажатием проверьте карточку. Команды `/approve ID CONFIRM` и `/reject ID` остаются резервным вариантом.

После сетевого таймаута поручение остаётся в статусе `submitting`: это означает, что результат у брокера неизвестен. Повтор той же команды использует прежний idempotency UUID, а не создаёт новую заявку. `/kill` блокирует новые отправки, но не управляет уже исполненной позицией.

Полностью автономная и реальная торговля здесь намеренно отсутствует: сначала нужно подтвердить sandbox-цикл, реализовать защитные выходы и сверку фактического исполнения.

Для подготовки реального дневного счёта существующий `T_INVEST_TRADING_TOKEN`
можно оставить в прежнем поле и явно назначить ему `T_INVEST_TRADING_TOKEN_ROLE=live`.
Он попадёт только в read-only live-preflight; отдельный `T_INVEST_LIVE_TOKEN` тогда
не обязателен. Если оба поля заполнены разными значениями для live-роли, запуск
останавливается с безопасной ошибкой. Пустой sandbox-ключ не заменяется live-ключом.
`T_INVEST_LIVE_ACCOUNT_ID` выбирает дневной профиль, не недельный или виртуальный;
`T_INVEST_LIVE_CAPITAL_RUB` задаёт его реальный бюджет и не меняет начальный
sandbox-остаток. Смена этих параметров сама не включает торговлю.

### Разовая настройка подтверждённого дневного профиля

Если прямой SSH оператора недоступен, workflow **Prepare daily read-only profile**
использует существующее production SSH-подключение проекта. Он запускается только
вручную на `main`, не по расписанию или кандидату, и разделяет блокировку с deploy.
Без `apply=true` выполняется только dry run; явный `apply=true` меняет ровно три
несекретных поля: `T_INVEST_TRADING_TOKEN_ROLE=live`,
`T_INVEST_LIVE_CAPITAL_RUB=500`, `T_INVEST_SANDBOX_INITIAL_BALANCE_RUB=1000`.
Значения уже сохранённых токенов не меняются и не передаются в GitHub.

Перед применением проверяются текущий SHA сервера, тот же контейнерный образ,
отключённое исполнение, включённый kill, подтверждённая приватная подготовка,
отсутствие unresolved/accepted поручений и раздельные уже выбранные счета.
Кандидат конфигурации проверяется без сети до замены `.env`. Создаётся приватная
резервная копия вне Git; после перечитывания обязательны фактический read-back и
неизменный снимок защиты. При ошибке старый файл восстанавливается только если
нет обнаруженного параллельного редактирования. Запросов брокеру, создания,
пополнения, заявок или активации sandbox этот workflow не делает. Его успех —
подтверждение конфигурации, не связи с брокером, прибыльности или live-готовности.

## Перед VPS

На сервер копируются только исходники, `.env` и Docker Compose. `.env` получает права `600`, в Git он не попадает. Токен T-Invest на сервере должен быть отдельным, сначала — только для чтения.

Образ сервиса устанавливает корневой и промежуточный сертификаты НУЦ Минцифры с официального источника и запускает Node с системным хранилищем CA. В образ также входит `librsvg2-bin`, который рендерит карточки на временную файловую систему контейнера; PNG не сохраняются на диске. Контейнер остаётся read-only, а `/tmp` — отдельный `tmpfs` с обычными безопасными правами `1777`, `noexec` и `nosuid`. CI запускает реальный PNG-рендер в контейнере с этими же ограничениями.

Оставьте в `.env` стандартное значение:

```dotenv
T_INVEST_TRANSPORT=fetch
```

После deploy проверьте TLS **из контейнера**:

```bash
docker compose exec telegram-service curl -sS -o /dev/null -w 'HTTP %{http_code}\n' \
  --connect-timeout 10 https://invest-public-api.tbank.ru/rest
```

`HTTP 404` здесь означает успешное TLS-соединение с базовым REST-маршрутом. Запрещены `curl -k`, `NODE_TLS_REJECT_UNAUTHORIZED=0` и любые отключения проверки сертификата.

Если `/preview` прислал текст «Карточка не сформировалась», откройте последние сообщения сервиса:

```bash
docker compose logs --tail=50 telegram-service
```

В рабочем образе команда `npm run smoke:candidate-card` должна завершаться строкой `Candidate card render smoke passed`. Этот тест не обращается к Telegram, T-Invest или сети.

Контейнер намеренно не публикует порты и хранит SQLite в Docker volume. Перед переходом на сервер нужно отдельно настроить резервное копирование этого volume и проверить восстановление.

## Операционные команды

```bash
docker compose logs -f
docker compose ps
docker compose restart
docker compose down
```

`docker compose down` не удаляет журнал. Команда `docker compose down -v` удалит Docker volume с историей — её использовать нельзя без проверенной резервной копии.
