# Локальный intraday-сканер

## Что он делает

Сканер работает на компьютере или VPS. В обычном режиме `moex-liquid` он раз в сутки получает от T-Invest перечень акций, выбирает заранее проверенное ядро ликвидных тикеров основной доски TQBR в RUB и сам обновляет UID, лот и минимальный шаг цены. Поэтому `.env` не содержит вручную найденных идентификаторов инструментов.

У T-Invest API нет единого endpoint с достоверным рейтингом ликвидности всего рынка. Поэтому вселенная состоит из прозрачного ядра крупных акций, а перед анализом входа сканер дополнительно требует минимальный средний оборот завершённой 5-минутной свечи. Это защищает от случайного попадания неликвидной бумаги и от дорогого сканирования всего списка акций.

Раз в пять минут сканер берёт последние шесть часов 5-минутных свечей по каждой активной бумаге. Он ранжирует ситуации по тренду, относительному объёму, обороту и волатильности. Стакан, последняя цена и статус торгов запрашиваются только для предварительно сильных ситуаций.

Он автоматически сохраняет карточку сценария только при всех условиях:

- 5-минутный тренд `up`;
- относительный объём не ниже 1.0;
- доступны ATR, нормальный стакан и API-торговля;
- расчёт позиции укладывается в лимиты риска;
- нет более свежего `candidate` для той же бумаги в пределах cooldown.
- в одном проходе не больше заданного числа кандидатов с лучшим рейтингом.

Кандидат содержит детерминированный план: цену входа по лучшему ask, стоп, цель, число лотов, размер позиции, модельные комиссии и проскальзывание на обе стороны, риск до стопа, чистый потенциал и R/R. Все числа относятся к моменту сканирования и сохраняются вместе с рыночным снимком.

Сам сканер **не создаёт брокерских заявок и не открывает paper-позиции**. Он создаёт материал для проверки. Отдельный sandbox-executor может подготовить поручение и отправить его только после явной Telegram-команды `/approve ID CONFIRM`; реальный счёт недоступен. В Telegram кандидат отображается PNG-карточкой; она не является указанием купить или продать.

`/market` в Telegram показывает последний проход: размер вселенной, сколько акций оказались ликвидными, сколько подтвердили тренд и объём, а также топ-5 ситуаций. Позиции из топа — диагностические near-miss, если до статуса `candidate` они не дошли; заявка по ним не готовится.

## Первый запуск

После merge и обновления проекта добавьте в локальный `.env`:

```dotenv
T_INVEST_INTRADAY_UNIVERSE=moex-liquid
T_INVEST_SCANNER_UNIVERSE_REFRESH_MINUTES=1440
T_INVEST_SCANNER_MAX_INSTRUMENTS=30
T_INVEST_SCANNER_MAX_CONCURRENT_REQUESTS=2
T_INVEST_SCANNER_MIN_AVERAGE_CANDLE_TURNOVER_RUB=1000000
T_INVEST_SCANNER_MAX_CANDIDATES_PER_SCAN=3
T_INVEST_SCANNER_INTERVAL_SECONDS=300
T_INVEST_SCANNER_LOOKBACK_MINUTES=360
T_INVEST_SCANNER_CANDIDATE_COOLDOWN_MINUTES=30
T_INVEST_SCANNER_SLIPPAGE_RATE=0.0005
```

Эти значения — штатный консервативный старт: 26 акций из ядра, не более двух одновременных запросов и не более трёх настоящих кандидатов за один проход. Статистика и top-5 доступны через `/market`.

Для отдельного эксперимента по одной бумаге оставьте явный режим совместимости:

```dotenv
T_INVEST_INTRADAY_UNIVERSE=watchlist
T_INVEST_INTRADAY_WATCHLIST='[{"instrumentId":"e6123145-9665-43e0-8413-cd61b8aa9b13","label":"SBER","lotSize":1,"priceStep":0.01}]'
```

Затем:

```bash
cd ~/dev/trading
npm run build
chmod 700 scripts/start-intraday-scanner.sh
npm run scan:intraday
```

Первый scan выполняется сразу, последующие — через несколько секунд после границы 5-минутного интервала. Строки JSON в терминале — журнал каждого прохода.

## Постоянный запуск через systemd user service

Скопируйте шаблон и включите сервис:

```bash
mkdir -p ~/.config/systemd/user
cp ~/dev/trading/docs/trading-intraday-scanner.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now trading-intraday-scanner
systemctl --user status trading-intraday-scanner
```

Логи:

```bash
journalctl --user -u trading-intraday-scanner -f
```

Остановить:

```bash
systemctl --user disable --now trading-intraday-scanner
```

Если процесс должен продолжать работать после выхода из графической сессии:

```bash
loginctl enable-linger "$USER"
```

Перед запуском service всегда проверьте ручной запуск `npm run scan:intraday`. Не помещайте токен в unit-файл: launcher читает его только из локального `.env`.
