# Исторические рыночные данные

## Назначение

`history:import` загружает минутные свечи за календарный год и сохраняет их в отдельную SQLite-базу. В режиме `auto` сначала используется быстрый годовой ZIP T-Invest, а при недоступности API — публичный MOEX ISS для основного режима торгов `TQBR`. Это основа для будущего backtest: правила проверяются на зафиксированных данных, а не на текущем состоянии рынка.

Импорт **не** запускает сканер, не открывает paper-позиции и не создаёт брокерские заявки. Ему достаточно существующего `T_INVEST_TOKEN` только для чтения.

Основной источник — [исторический архив T-Invest](https://developer.tbank.ru/invest/services/quotes/get_history): один ZIP-архив минутных свечей на инструмент и год. Резервный источник — [MOEX ISS candles](https://iss.moex.com/iss/reference/409) с серверной пагинацией. MOEX fallback сам разрешает тикер, лот и шаг цены, поэтому не зависит от `InstrumentsService/Shares`. Для одного `тикер + год` в базе остаётся только один авторитетный набор; смена источника не создаёт двойной каталог.

## Подготовка

В `.env` оставьте или добавьте:

```dotenv
T_INVEST_TOKEN=токен-только-для-чтения
T_INVEST_HISTORY_DATA_URL=https://invest-public-api.tbank.ru/history-data
T_INVEST_MARKET_DATA_PATH=.trading/market-data.sqlite
MOEX_ISS_BASE_URL=https://iss.moex.com/iss
```

`T_INVEST_MARKET_DATA_PATH` намеренно отделён от `T_INVEST_JOURNAL_PATH`: исторические минутные данные могут занимать существенно больше места, чем журнал сигналов. Папка создаётся с правами `700`, файл базы — с `600`.

На Ubuntu, где Node не доверяет цепочке Минцифры, используйте уже настроенный безопасный транспорт:

```dotenv
T_INVEST_TRANSPORT=system-curl
```

Проверка TLS остаётся включённой. Не используйте `curl -k` и не отключайте проверку сертификатов Node.js.

## Импорт

Из корня репозитория:

```bash
npm run build
npm run history:import -- --year 2025
```

Команда импортирует год для текущей настроенной intraday-вселенной. Для ограниченного прогона по одной или нескольким бумагам:

```bash
npm run history:import -- --year 2025 --ticker SBER,GAZP
```

Можно передать несколько лет:

```bash
npm run history:import -- --year 2025 --year 2026 --ticker SBER
```

По умолчанию используется `--source auto`. Для воспроизводимой диагностики источник можно зафиксировать:

```bash
npm run history:import -- --year 2023 --ticker SBER,GAZP --source moex
npm run history:import -- --year 2025 --ticker SBER --source tinvest
```

MOEX fallback поддерживает годы с 2015 по текущий. Он медленнее годового ZIP, использует ограниченную последовательную пагинацию и небольшую задержку между страницами, чтобы не создавать всплеск запросов к ISS.

Импорт идёт последовательно, чтобы не создавать всплеск запросов к API. Каждая строка результата — JSON без токена, например:

```json
{
  "status": "imported",
  "ticker": "SBER",
  "year": 2025,
  "storedCandleCount": 123456,
  "invalidRowCount": 0
}
```

Ошибочный инструмент не отменяет уже успешно сохранённые архивы; в конце команда завершится ошибкой, если хотя бы один импорт не удался.

## Контроль качества и повторный запуск

Импортер принимает только ZIP с одной CSV, содержащей `UID`, `UTC`, `open`, `close`, `high`, `low` и `volume`. Он проверяет принадлежность инструмента и года, геометрию свечи, объём и временную метку. Невалидные строки учитываются в логе; архив без хотя бы одной валидной свечи не сохраняется.

Для каждого набора в базе сохраняется SHA-256, тикер, источник (`tinvest` или `moex`), число исходных/отброшенных/дублирующихся строк, лот, шаг цены и время импорта. Replay использует именно этот provenance, а не текущий снимок API. Повторный запуск того же года безопасен: набор `тикер + год` заменяется транзакционно, дублей между источниками не остаётся. Старые строки provenance автоматически мигрируют с источником `tinvest`. ZIP-файлы и токен в базе не хранятся.

## Docker на VPS

На сервере после deploy можно выполнить одноразовый импорт в тот же Docker volume:

```bash
cd /opt/andstrel/trading
docker compose run --rm telegram-service node dist/history-import.js --year 2025 --ticker SBER
```

Перед массовым импортом нужна резервная копия Docker volume. Команда `docker compose down -v` удаляет и журнал, и историческую базу.

## Первый импорт 2025 без ручного SSH

В репозитории есть workflow **Bootstrap 2025 historical data**. После merge изменений в workflow или в коде архивного импортера он использует deploy Secrets из защищённого GitHub Environment `production`, ждёт освобождения того же deploy-lock и запускает импорт на VPS. Его также можно запустить вручную после неудачного или прерванного прогона, выбирая только `main`. Токен T-Invest остаётся только в серверном `.env`.

В этот первый прогон входит фиксированная `liquid-20` выборка из основной intraday-вселенной:

```text
SBER, SBERP, GAZP, LKOH, ROSN, NVTK, TATN, TATNP, SNGS, SNGSP,
GMKN, PLZL, CHMF, NLMK, MTSS, MGNT, MOEX, AFLT, ALRS, HYDR
```

Перед скачиванием workflow требует минимум 4 GiB свободного места на разделе `/opt/andstrel/trading`. Обычные последующие deploy не повторяют импорт: workflow реагирует только на изменения, относящиеся к архивному импортеру, либо на ручной запуск. Результат и число загруженных свечей видны в GitHub Actions log.

После успешного bootstrap workflow **Replay 2025 historical data** запускается вручную из GitHub Actions. Такой порядок не допускает запуска backtest до заполнения общего Docker volume.

Для исследовательского каталога нескольких лет используется отдельная команда, которая не запускает replay и не меняет production-контур:

```bash
npm run research:catalog -- \
  --year 2023 --year 2024 --year 2025 \
  --ticker SBER,GAZP \
  --lookback-minutes 30 --step-minutes 5 --outcome-minutes 15,30,60
```

Подробное описание таблиц, временной отсечки и поиска похожих ситуаций находится в [документе исследовательского каталога](RESEARCH_DATASET.md).

## Граница текущего этапа

Импорт создаёт качественный набор входных минутных данных, но сам по себе не доказывает доходность стратегии. Воспроизводимый replay с комиссиями, неблагоприятным проскальзыванием и фиксированным OOS-периодом описан в [документе backtest](BACKTEST.md); walk-forward для следующей версии стратегии остаётся отдельным этапом.
