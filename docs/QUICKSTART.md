# Запуск и управление ботом

Для автономной проверки всех трёх алгоритмов после сборки: `npm run smoke:strategy-bot`. Данные искусственные; сеть и брокер не используются. Это не backtest и не результат доходности.

## Один раз на компьютере или сервере

Нужны Node.js 22+, npm, Git и работающий Docker Engine/OrbStack с Compose v2. Запустите Docker перед развёртыванием. `npm run setup` выполняет локальную подготовку, не устанавливает Docker и не настраивает счета.

```bash
git clone https://github.com/AndStrel/trading.git ~/dev/trading
cd ~/dev/trading
npm ci
npm run setup
```

Если проект уже клонирован, работайте в его каталоге. `setup` создаст отсутствующий `.env` из текущего `.env.example` с правами `600`, а `.trading` и `.trading/relay` — с правами `700`. При повторном запуске содержимое `.env` останется прежним; новые поля в старый файл нужно добавить по `.env.example`. Файлы и каталоги symlink не поддерживаются.

Откройте `.env` локальным редактором и заполните:

| Поле | Что требуется |
|---|---|
| `T_INVEST_TOKEN` | Отдельный токен T-Invest с правами только чтения |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота, полученный у BotFather |
| `TELEGRAM_ALLOWED_CHAT_IDS` | Сначала можно оставить пустым для получения своего ID |
| `T_INVEST_EXECUTION_MODE` | `disabled` при первом запуске |

Токены заполняются только в `.env` машины запуска. Файл исключён из Git; не помещайте его в описания PR, командные аргументы или чат. `.env.example` содержит только публичные поля и пустые значения секретов.

Проверьте конфигурацию и запустите сервис:

```bash
npm run doctor
npm run deploy
```

`deploy` сначала собирает образ, затем проверяет конфигурацию в новом образе и
только после успеха заменяет `telegram-service` без повторной сборки. Ошибка
сборки или preflight останавливает команду до замены работающего контейнера.
Preflight не обращается к брокеру, не открывает журнал и не печатает секреты.

`doctor` использует фактическую схему сервиса. Переменные окружения запуска имеют приоритет над `.env`, как у `node --env-file`. Он показывает готовность локальной конфигурации и предупреждения; сетевое соединение, права токена у брокера и наличие денег отдельно проверяются работающим ботом. Пустой allowlist при первом запуске — предупреждение, не ошибка.

В Telegram отправьте `/start`, сохраните полученный ID в `TELEGRAM_ALLOWED_CHAT_IDS` и повторите `npm run deploy`. Допускается до 10 ID через запятую. Бот проверяет доступ к командам; для Mini App нужен разрешённый личный чат. Откройте меню, затем состояние рынка и кандидатов. `/preview` проверяет доставку демонстрационной карточки, `/status` показывает состояние сканера. `/kill` запрещает новые входы; открытая позиция этим действием не закрывается.

## Стратегия и выбранные активы

Выберите стратегию в Mini App. Стартовый выбор задаётся `T_INVEST_TRADING_STRATEGY_ID`:

| ID | Подход |
|---|---|
| `trend-momentum-v1` | Движение по тренду при подтверждённом объёме |
| `opening-range-breakout-v1` | Пробой диапазона начала сессии |
| `vwap-reclaim-v1` | Возврат выше средневзвешенной цены после отката |

`T_INVEST_INTRADAY_UNIVERSE_TICKERS` ограничивает вселенную тикерами через запятую; пустое значение выбирает стандартный курируемый список. В шаблоне небольшой дневной профиль начинается с `VTBR,IRAO`; доступность конкретного лота определяется актуальной ценой, лотом, затратами и лимитами. `T_INVEST_STRATEGY_SESSION_START=09:10` задаёт московскую точку отсчёта стратегии. Она не заменяет расписание биржи: свежий брокерский статус проверяется перед допуском кандидата.

Если сохраняете старый режим `T_INVEST_INTRADAY_UNIVERSE=watchlist`, каждый элемент
`T_INVEST_INTRADAY_WATCHLIST` должен иметь `label` с биржевым тикером: например,
`"label":"VTBR"`. Допустимы 1–16 символов `A–Z`, цифр, точки и дефиса; подпись
«Банк ВТБ», пустой label или брокерский UID вместо тикера не подходят для выбора
активов. `instrumentId`, `lotSize` и `priceStep` сохраняются отдельными полями.
Пустой список watchlist, отсутствующий или невалидный label завершатся
ошибкой конфигурации; `npm run doctor` покажет `CONFIGURATION: error`. Добавьте
хотя бы один инструмент с тикером, затем повторите doctor. Раньше интерфейс мог использовать
`instrumentId` вместо подписи; такая неявная миграция больше не применяется. В
режиме `moex-liquid` это требование к старому watchlist не влияет на запуск.

Смена стратегии меняет ревизию настройки и требует нового расчёта рекомендаций. Старые карточки не подходят для новой настройки. Детальные правила и источники: [STRATEGIES](STRATEGIES.md). Комиссия по умолчанию `0.003` означает **0,3% на каждую сторону**; `0.0005` проскальзывания — **0,05% на сторону**. Дневной prepare-профиль не опускает комиссию ниже 0,3% даже при меньшем значении в старом `.env`.

## Telegram Mini App

Кнопки Telegram работают без домена. Для Mini App нужны отдельный HTTPS-домен и reverse proxy до опубликованного Compose-порта `127.0.0.1:8088`. Для существующего поддомена `bot.brewnote.net` задайте:

```dotenv
TELEGRAM_MINI_APP_ENABLED=true
TELEGRAM_MINI_APP_URL=https://bot.brewnote.net
TELEGRAM_MINI_APP_HOST=0.0.0.0
TELEGRAM_MINI_APP_PORT=8080
```

Повторите `npm run doctor` и `npm run deploy`, затем откройте панель внутри Telegram. `0.0.0.0` нужен только внутри контейнера; порт хоста остаётся loopback. Команда развёртывания не выдаёт сертификат и не меняет nginx других проектов. Настройка домена, HTTPS, проверка доступа и откат: [TELEGRAM_MINI_APP](TELEGRAM_MINI_APP.md).

## Подтверждённое sandbox-исполнение

Исполнение `disabled` не создаёт заявки. Для отдельной песочницы используются собственный токен и подготовленный виртуальный счёт. В `.env` укажите:

```dotenv
T_INVEST_EXECUTION_MODE=sandbox
T_INVEST_SANDBOX_TOKEN=
T_INVEST_SANDBOX_INITIAL_BALANCE_RUB=1000
T_INVEST_EXECUTION_MAX_ORDERS_PER_DAY=3
T_INVEST_EXECUTION_MAX_DAILY_RISK_RUB=60
T_INVEST_SANDBOX_PROTECTION_ENABLED=true
T_INVEST_SANDBOX_LOSS_GUARD_ENABLED=true
T_INVEST_SANDBOX_SESSION_CLOSE_ENABLED=true
```

Сохраните отдельность ролей `read-only`, `sandbox` и `live`. Поле `T_INVEST_TRADING_TOKEN` поддерживает старую совместимость: роль задаётся `T_INVEST_TRADING_TOKEN_ROLE`; разные значения canonical/alias для одной роли запрещены. Пустой sandbox-токен не заменяется токеном другого назначения.

```bash
npm run doctor -- --profile sandbox
npm run deploy
```

Доктор проверяет только настройки. Подготовка виртуального счёта и его приватное доказательство выполняются по [SANDBOX_EXECUTION](SANDBOX_EXECUTION.md). В Telegram `/execution` показывает текущую готовность, `/execution_arm SANDBOX` проверяет подготовленный счёт, а новая карточка даёт подтверждение конкретной сделки. Arm не создаёт и не пополняет счёт. Защита и контроль конца сессии работают только для поддерживаемого sandbox-контура; после таймаута сначала сверяется исход прежней заявки с её прежним idempotency ID.

Код исполняет только sandbox. Live-токен используется для подготовки дневного профиля и read-only проверок; выбор стратегии и успешный `doctor` не добавляют live-исполнение.

## Обычные операции и обновление

```bash
npm run status
npm run logs
npm run stop
```

Для обновления в чистом checkout:

```bash
git pull --ff-only
npm ci
npm run doctor
npm run deploy
```

`setup` не сбрасывает настройки, `deploy` повторно проверяет конфигурацию перед заменой только сервиса с сохранением volume. SQLite-журнал и рыночная история лежат в именованном volume `trading-journal` в `/app/data`. Не выполняйте `docker compose down -v`: это удалит историю. Резервная копия и восстановление volume должны быть проверены до смены машины. Откат использует прежний Git-коммит/образ и прежний `.env`; подробности — [DEPLOY_TELEGRAM_SERVICE](DEPLOY_TELEGRAM_SERVICE.md).

## MCP и локальный процесс

MCP не требует Telegram или Docker:

```bash
npm run doctor -- --profile mcp
npm run build
npm run smoke:tinvest
```

Настройте MCP-клиент на абсолютный путь `scripts/start-local.sh` этого checkout; токен в конфиг MCP не копируется. `list_accounts` даёт ID для `T_INVEST_INTRADAY_ACCOUNT_ID` и `T_INVEST_SWING_ACCOUNT_ID`, если нужны соответствующие read-only портфели. Для локального Telegram-процесса после сборки используйте `npm run service:telegram`; для отдельного сканера — `npm run scan:intraday`. Не запускайте два Telegram polling-процесса с одним ботом.

## Если запуск не удался

| Наблюдение | Следующее действие |
|---|---|
| Docker сообщает denied/daemon unavailable | Запустить Docker/OrbStack и проверить доступ текущего пользователя; `doctor` Docker не проверяет |
| Doctor сообщает CONFIGURATION | Сверить типы полей и роли токенов с `.env.example`; сырые ошибки и значения скрыты |
| Команды не принимаются | Получить ID через `/start`, сохранить allowlist, пересоздать сервис |
| Кандидатов нет | Посмотреть рынок и причины отказа; сравнить капитал с стоимостью лота и затратами |
| Mini App не открывается | Проверить HTTPS, reverse proxy и host `0.0.0.0` внутри контейнера; открыть через Telegram |
| В Node есть ошибка цепочки CA | Docker-образ устанавливает CA из официального источника внутри контейнера; локальный `system-curl` использует уже доверенный CA системы. Проверка TLS не отключается |
| Sandbox-заявка осталась submitting | Сверить `/orders` и `/execution`; исход неизвестен, новую заявку вместо прежней не создавать |

Снимок локальной диагностики без секретов можно получить так:

```bash
npm run doctor -- --json
```
