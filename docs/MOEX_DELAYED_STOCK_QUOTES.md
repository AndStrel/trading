# Локальный сбор задержанных котировок MOEX

Для проверки реалистичности расходов TMON подготовлен read-only сбор лучших заявок BID/OFFER из публичного MOEX ISS. Он не использует брокерский токен, не выставляет заявки и записывает только обезличенные рыночные данные в игнорируемую Git папку `.trading/quotes/`.

После `npm run build` один замер: `QUOTE_TICKER=TMON QUOTE_SAMPLES=1 node dist/research-moex-stock-quote-capture.js`. Поддержаны также `TGLD` и `T`. Несколько замеров выполняются с интервалом 60 секунд, максимум 480. Принимаются только строки текущего стакана TQBR со статусом нормальных торгов, положительными и непересечёнными BID/OFFER. Каждый запрос записывается в `moex-delayed-TMON-attempts.jsonl`, включая закрытый рынок, отсутствующую заявку и сетевую ошибку; исходный публичный ответ сохраняется для повторной проверки. Повторы котировок остаются отдельными наблюдениями, а не новыми независимыми ценовыми событиями.

Локальный контейнер `quote-capture` запускается через `docker compose --profile quotes up -d --no-deps quote-capture` после сборки. Он автоматически делает не более одного публичного запроса в минуту **по будням с 10:15 до 17:20 МСК включительно**, максимум 426 запросов в день. Вне окна он ожидает без сетевых запросов. Проверяется только день недели, не биржевой календарь: в праздничный будний день закрытый рынок будет записан как отклонённая попытка. Для остановки: `docker compose --profile quotes stop quote-capture`. После перезапуска Docker контейнер возобновится автоматически; пока компьютер или Docker выключен, данные не собираются. Профиль не подключает `.env`, брокерский токен или остальные данные `.trading`, а сборка задаёт `INSTALL_TINVEST_CA=false`. Он не выставляет заявки. Для разового замера без контейнера: `QUOTE_TICKER=TMON QUOTE_SAMPLES=1 node dist/research-moex-stock-quote-capture.js`.

Поле `spreadBps` показывает полный наблюдаемый спред, но данные MOEX ISS задержаны. Это не цена, по которой можно было исполнить заявку в момент наблюдения, и не доказательство доступной глубины или заполнения. Для допуска стратегии нужны котировки в момент принятия решения, проверка реальных комиссий и ликвидности, а затем независимая проверка без подгонки правила.

Проверить качество накопленного журнала можно после сборки командой `node dist/research-tmon-quote-quality.js`. Отчёт `.trading/quotes/tmon-quote-quality.json` сохраняет SHA-256 исходного журнала, число принятых/отклонённых запросов, уникальные обновления (повторы не удваивают выборку), медиану и 90-й процентиль наблюдаемого спреда, покрытие утреннего и вечернего окон по датам. При подсчёте обновлений изменение одного лишь системного времени `SYSTIME` не считается новой котировкой: нужны изменения времени обновления `UPDATETIME`, лучшей цены или её глубины. Отчёт также показывает возраст лучшей заявки между биржевыми `UPDATETIME` и `SYSTIME`; неизвестный возраст выделяется отдельно. Это диагностическое время внутри задержанного источника, не фактическая давность доступной нам исполнимой заявки. Эти цифры нельзя считать независимыми сделками или исполнимыми котировками.

Два пробных запроса 26 сентября 2026 года (суббота), включая запуск в контейнере, дали `0/2` принятых котировок. В журнале обе попытки: HTTP 200, `status=rejected`, исходные публичные ответы сохранены, нормальной котировки нет. Замер рабочего спреда ещё не получен. Гипотеза TMON остаётся непроверенной, торговые заявки не разрешены.

28 сентября 2026 года (понедельник) торговое окно также **не было записано**: журнал по-прежнему содержит только две субботние попытки. Проверка Docker показала, что контейнер начал текущую работу в 19:17:58 МСК, уже после окна 10:15–17:20. Это пропуск наблюдения, не отрицательный результат стратегии и не доказательство отсутствия торгов: публичные минутные свечи MOEX TMON/TQBR за 28 сентября содержат 133 минуты со сделками в 10:00–17:00. Причина отсутствия контейнера в течение сессии отдельно не установлена. Для следующего дня компьютер и Docker должны оставаться включёнными в торговое окно; `restart: unless-stopped` возобновляет работу после запуска Docker, но не восстанавливает пропущенный стакан задним числом.

Исторические внутридневные лучшие заявки MOEX доступны как отдельный архивный продукт Top of Book (тип B), а не как бесплатные минутные свечи сделок. До получения такого архива или новых наблюдений нельзя закрыть 43 неизвестных выхода TMON за 2025 год. Источник: [исторические продукты MOEX](https://www.moex.com/a2863).

## Граница применимости после проверки маршрута T-Invest

Этот контейнер собирает **TMON/TQBR на MOEX**, а не **TMON@/SPBRU**. На 28 сентября 2026 года read-only карточка T-Invest для первого режима сообщала `apiTradeAvailableFlag=false`, а для второго — `true`; это разные торговые режимы и UID при одном ISIN. Поэтому будущая статистика спреда MOEX/TQBR **не доказывает цену исполнения через доступный брокерский маршрут SPBRU** и не может калибровать расходы SPBRU-бэктестов. Она остаётся полезной для качества публичного MOEX-источника и сопоставления площадок, но ни одна стратегия не получает торгового допуска на её основании.

Разовый read-only стакан TMON@/SPBRU через T-Invest API в 20:09:07 МСК 28 сентября содержал bid 165,06 ₽ и ask 165,07 ₽ с временной меткой формирования `2026-09-28T17:09:07.382368886Z` — спред 0,01 ₽. Это второй точечный снимок, а не независимая выборка для вероятности исполнения; огромные отображённые объёмы не приравниваются к гарантированно доступной ликвидности. Автоматический сбор SPBRU через брокерский токен **не включён** и не вытекает из разрешения на публичный MOEX-сбор. Для проверки исполнения нужен отдельный безопасный ряд именно SPBRU bid/ask и размеров очереди, затем контроль времени, повторов, задержки и результата заявок; никаких заявок здесь нет.

Проверка [официального раздела подключения к API СПБ Биржи](https://spbexchange.ru/stocks/tech_solutions/api/) не выявила свободного публичного REST-стакана: описанное там подключение требует документов и сертификата участника торгов. [Шлюз рыночных данных биржи](https://spbexchange.ru/stocks/tech_solutions/interface/) описан как бинарный/FIX-FAST поток. Это не доказательство, что другого публичного способа не существует; пока у проекта нет проверенного публичного источника SPBRU bid/ask, который можно было бы безопасно подставить вместо брокерского read-only API.

Источники: [MOEX ISS](https://iss.moex.com/iss/reference/), [условия распространения данных MOEX](https://www.moex.com/a2920).
