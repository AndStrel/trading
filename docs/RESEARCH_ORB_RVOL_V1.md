### Ограничения предыдущей диагностики

- `calculateExcursions` в `src/backtest/replay.ts` включает всю свечу выхода.
  При внутриминутном выходе её экстремумы могут относиться к движению после
  закрытия позиции. В журнале 30 выходов точно по стопу имеют MAE > 1R;
  например MTSS 2025-04-02: вход 221,5, стоп и выход 220,5, MAE 1,55R.
  Это не означает, что позиция действительно пережила такой убыток до выхода.
- MFE до выбранного выхода зависит от самого правила выхода. Его среднее
  нельзя интерпретировать как потенциал движения на независимом горизонте.
- `zero-cost` пересчитывает планы/размеры/цели; `relaxed-portfolio` меняет
  также максимальный размер позиции. Сравнение этих сценариев не изолирует
  чистое влияние одного фактора. Для разложения издержек нужен один и тот же
  журнал входов, выходов и количеств.
- Журнал исполненных старых сигналов не содержит всех событий рынка.
  По нему нельзя проверить новую стратегию начального диапазона.
- Все просмотренные части 2025 года считаются исследовательскими.
  Название старой фазы `out_of_sample` не делает её независимой для новой идеи.

## 2. Проверяемая гипотеза и альтернативы

Гипотеза: первый подтверждённый пробой начального диапазона основной сессии
на повышенном относительном объёме имеет более сильное последующее движение
вверх, чем сопоставимый пробой на обычном объёме; эффекта хватает на издержки.
Повышенный объём — наблюдаемый признак активности, НЕ доказательство покупок
институционалов, новости или конкретной причины движения.

Первичная исследовательская метрика: доходность от следующего минутного
открытия до открытия через 60 минут, после базовой модели издержек.
Горизонты 15, 30 и 120 минут — описательные, не способ задним числом выбрать
единственный положительный результат. Нулевая гипотеза: устойчивого
положительного эффекта после издержек нет.

| Идея | Решение для первого эксперимента |
| --- | --- |
| Пробой начального диапазона + повышенный объём | Первый кандидат: можно исследовать на имеющемся типе минутных данных |
| Покупка после неудачного пробоя вниз / возврат к среднему | Отдельная будущая гипотеза; не смешивать с первой, иначе непонятен источник эффекта |
| Многодневное продолжение тренда | Отдельное исследование: другие горизонты, гэпы, дивиденды и перенос риска через ночь |

Основание из литературы: Zarattini, Barbon и Aziz исследовали ORB на акциях
США за 2016–2023 годы; отбор по относительному объёму улучшал результаты
их модели. Это другая выборка, с long/short, возможным плечом и иной моделью
комиссий. В их сравнении 30-минутный вариант заметно уступал 5-минутному.
Следовательно, статья поддерживает проверку признака активности, но не
доказывает прибыльность нашего 30-минутного long-only варианта на МОЕХ.

[Первичный источник: A Profitable Day Trading Strategy For The U.S. Equity Market](https://concretumgroup.com/wp-content/uploads/2026/02/A-Profitable-Day-Trading-Strategy-For-The-U.S.-Equity-Market.pdf).

## 3. Фиксированные правила кандидата v1

Числа ниже — заранее выбранная начальная конфигурация, не найденный оптимум.
Выбор 30 минут мотивирован проверкой более крупного движения при наших
издержках; это предположение, которое может не подтвердиться.

### Данные и часы

- Исследовательская корзина: те же 20 тикеров старого теста. Не выбирать
  задним числом только прибыльные акции. Такая корзина не доказывает
  работоспособность на всём историческом рынке: остаётся риск смещения отбора.
- Только полные обычные сессии по календарю биржи; дополнительные выходные,
  специальные расписания и аукционы не смешивать с обычными сессиями.
- `T0` — начало непрерывного торгового периода основной сессии данного
  инструмента в конкретную дату. Не начало любой утренней торговли.
- Диапазон: `[T0, T0 + 30 минут)`. Фиксируем его максимум H, минимум L
  и объём V только после завершения всех 30 минут.
- `RVOL30 = V / median(V_previous_20_comparable_sessions)`.
  Референс включает только предыдущие полные сопоставимые сессии, без текущей.
  После изменения расписания/единиц объёма сначала накапливаем 20 новых
  сопоставимых наблюдений. Объёмы в акциях требуют корректного размера лота
  на историческую дату; сплиты и изменения лота нельзя игнорировать.
- При неизвестных исторических часах, корпоративном действии без корректной
  нормализации или неполном стартовом диапазоне событие отмечается как
  непроверяемое. Не подставлять сегодняшние метаданные как историческую истину.

По [текущему расписанию MOEX](https://www.moex.com/s1167) основной торговый
период обычных акций, допущенных к утренней сессии, начинается в 09:00 МСК;
для акций без утренней сессии предусмотрен аукцион и непрерывные торги с 09:10.
Это не подтверждение таких же часов для 2025 года. Перед историческим
экспериментом нужна датированная таблица расписаний.

### Сигнал, исполнение и выход

1. Long-only, без плеча. `RVOL30 >= 1.5`.
2. Первый завершённый 5-минутный бар после построения диапазона, закрывшийся
   выше H. Бар не должен пересекать границу стартового диапазона; сигнал
   допустим до `T0 + 120 минут`, не включая эту границу.
3. Модельный вход — открытие непосредственно следующей минутной свечи
   плюс неблагоприятное проскальзывание. Нет свечи — нет придуманного входа.
   Если её открытие уже не выше H, пропуск; повторного входа в этот день нет.
4. Стоп — L минус один исторически корректный ценовой шаг. Расстояние
   `R_price = entry_reference - stop`. Тейк — `entry_reference + 2 * R_price`,
   округлённый вверх к ценовому шагу.
5. До входа проверяется бюджет издержек: оценка полного входа-выхода
   не выше одной трети денежного первоначального риска до издержек.
   При базовых 0,20% на круг это приблизительно требует расстояния до стопа
   не менее 0,60% цены. Это отсечка слишком дорогих сделок, не доказательство
   положительного математического ожидания. При провале не расширять стоп
   искусственно и не повышать тейк; пропустить событие.
6. Выход по стопу, тейку или через 120 минут после входа; в любом случае
   не позднее чем за 5 минут до окончания непрерывных основных торгов.
   Запланированный временной выход моделируется по открытию точной минутной
   свечи. Никакого переноса позиции на следующую сессию.
7. Если после проверки открытия одна OHLC-минута касается обоих уровней,
   считать первым стоп. Гэп через стоп исполняется по доступному открытию,
   а не по недоступной цене стопа. Касание тейка по OHLC не гарантирует
   реального исполнения лимитной заявки; это ограничение модели.
8. Один кандидат на тикер в день. Отклонённый из-за данных, цены, стоимости
   или портфельных лимитов кандидат также записывается с причиной отказа.

### Портфель и расходы

- Начальный модельный капитал 100 000 ₽; позиция не больше 50 000 ₽;
  одновременно не больше двух позиций. Учитывать комиссию и остаток cash.
- Плановый убыток на стопе вместе с модельными расходами не больше 500 ₽.
  Размер округлять вниз по лотам. Гэп/ликвидность способны превысить этот
  плановый предел: он не является гарантированным максимумом потерь.
- При одновременных сигналах порядок: более высокий RVOL30, затем тикер
  по алфавиту. Использовать только сведения, доступные на момент выбора.
- База: комиссия 0,05% и проскальзывание 0,05% на каждую сторону — около
  0,20% на круг. Это прежняя модель проекта, не проверка реального тарифа
  пользователя и не измеренный спред.
- Стресс: при той же комиссии увеличить проскальзывание до 0,10% и 0,15%
  на сторону: приблизительно 0,30% и 0,40% на круг. Проскальзывание включает
  модельную поправку на spread/исполнение; не учитывать один расход дважды.
- Для чистого анализа издержек сначала сохранить неизменными сделки и
  количества. Отдельно пересчитать стратегию с обновлённым cost-фильтром,
  sizing и cash; явно подписать, что это другой портфель.

## 4. Как исследовать закономерность

1. Из полного минутного архива построить ВСЕ первые пробои, а не только
   сделки, вместившиеся в портфель. Сохранить timestamp доступности каждого
   признака, RVOL, ширину диапазона, цену входа и причины пропусков.
2. Сравнить события с `RVOL30 >= 1.5` и обычные пробои. Для содержательного
   контроля учитывать тикер, календарный период, время относительно T0
   и ширину диапазона; границы групп фиксировать на исследовательской части.
   При отсутствии сопоставимых контролей не выдумывать сравнение.
3. Измерять первичную 60-минутную доходность независимо от стопа/тейка
   будущей стратегии. Точки после гэпов/отсутствующих свечей не интерполировать;
   учитывать их как непроверяемые и показывать долю/распределение пропусков.
4. Отдельный replay: базовый ORB с теми же правилами без RVOL-фильтра и
   кандидат v1 с фильтром. Не менять одновременно выходы, риск и набор акций.
   Улучшение среднего не равно улучшению портфеля — показать оба результата.
5. Показать результаты по месяцам, тикерам и режимам расписания; оценить
   долю общего результата, приходящуюся на лучший день и лучший тикер.
   Нельзя считать 20 коррелированных акций за один день 20 независимыми опытами.

Не использовать существующий MAE/MFE как точное движение до выхода.
Для минутной свечи с внутриминутным исполнением нужны границы возможного
экстремума/флаг неопределённости, а не произвольное восстановление пути цены.
Для выхода на открытии экстремумы последующего движения этой минуты исключаются.

## 5. Независимая проверка и решение

- 2025 — исследовательский период. Возможные 2023–2024 — дополнительные
  исторические проверки после загрузки и проверки метаданных, не автоматически
  независимый тест, если их результаты использовались для выбора правил.
- Кандидат на отложенную проверку: 2026-01-01 — 2026-08-31, ТОЛЬКО если
  подтвердится, что этот отрезок ещё не использовался при разработке.
  До фиксации версии и правил не открывать его результаты для этой стратегии.
- Если неиспользованного исторического отрезка нет, независимую проверку
  переносим на будущие бумажные наблюдения после фиксации версии.
- После вскрытия отложенного теста любое изменение — новая версия с записью
  причины и новым независимым периодом. Учёт всех испробованных вариантов
  обязателен; один удачный результат после множества попыток не считается
  подтверждением. [Обоснование риска переоптимизации](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf).

Предварительные ворота для продолжения исследования, не для реальных заявок:

1. Не менее 100 сделок и 50 различных дней с событиями на независимом
   периоде; это нижняя организационная граница, НЕ гарантия достаточной мощности.
2. Положительная net-доходность и profit factor > 1 в базе и при расходах
   0,30% на круг; при 0,40% показать результат без подмены условий.
3. 95%-й интервал среднего дневного net-PnL, рассчитанный блочным bootstrap
   по 5 последовательным торговым дням с сохранением всех акций и дней без
   сделок внутри блока, не включает ноль. Интервал не исправляет сам по себе
   подгонку/выбор лучшей версии из многих. Для сравнения с контролем — парные
   дневные разности на тех же блоках.
4. Результат не становится отрицательным после удаления лучшего дня или
   всех сделок лучшего тикера. Реализованную и внутридневную переоценённую
   просадку показывать отдельно; допустимый предел для live здесь не назначается.
5. При нехватке данных/широком интервале вывод: «не подтверждено», а не
   «прибыльно» или «эффекта точно не существует». Устойчивый отрицательный
   результат закрывает v1; не запускать бесконечный перебор порогов.

## 6. Датированный календарь для replay 2025

Для запуска 2025 используется версия календаря `moex-equities-2025-v1`.
Она отвечает только на вопрос «можно ли считать эту дату сессией»; часы
основного окна по-прежнему передаются явно через `--session-start` и
`--session-end`.

- Даты 1–2, 4–5 и 7 января, 8 марта, 1 и 9 мая, 12 июня, 4 ноября и
  31 декабря исключены как даты без торгов фондового рынка.
- 3, 6 и 8 января сохранены как специальные торговые даты.
- Выходные до 1 марта исключены. Выходные начиная с 1 марта не выкидываются
  автоматически: в 2025 фондовый рынок проводил экспериментальные
  дополнительные сессии выходного дня.
- Любая исключённая дата попадает в `dataQuality.calendarRejectedSessionCount`
  и в `rejections` с причиной `outside_trading_calendar`; её объём не
  попадает в RVOL lookback.

Календарь зафиксирован в коде как исследовательская версия и не является
универсальным календарём для других лет. Источник сверки — [торговый календарь
Московской биржи](https://www.moex.com/ru/tradingcalendar/) и опубликованные
уведомления MOEX по праздничным датам. Изменение календаря требует новой
версии эксперимента и нового прогона.

## 7. Следующий программный этап

В этом документе нет результата нового бэктеста. Доступные локальные
артефакты содержат отчёты; базы полных минутных свечей в рабочем каталоге нет.
Нужен существующий серверный архив либо его воспроизводимый read-only экспорт.

После загрузки архива исследовательский сборщик запускается вручную через
GitHub Actions workflow **Research ORB RVOL 2025**. Для 2025 команда уже
применяет версионированный календарь дат; перед запуском нужно отдельно
проверить часы основной сессии и передать их. Для
локального запуска команда имеет такой вид:

```bash
npm run build
npm run backtest:replay:orb-rvol -- \
  --year 2025 \
  --session-start 10:00 \
  --session-end 18:40
```

`--session-start` и `--session-end` обязательны. В отчёт записывается
фиксированный профиль часов и версия календаря дат; часы всё равно требуют
сверки с историческим расписанием. По умолчанию берётся liquid-20; отдельный поднабор можно
задать через `--ticker SBER,GAZP`, но такой запуск нельзя сравнивать с
полной корзиной.

Порядок реализации:

1. Исправить и протестировать интерпретацию MAE/MFE, разделив точные
   экстремумы и неопределённость свечи выхода. Сначала исправить измеритель.
2. Добавить датированное расписание и проверки исторических lot/priceStep;
   неоднозначные даты и корпоративные действия отражать явно.
3. Добавить отдельный read-only сборщик событий ORB и отчёт фиксированных
   горизонтов; подключать портфельный кандидат только после проверки признака.
4. Для 2026 добавить воспроизводимый выбор диапазона дат и cutoff данных.
   Текущий `backtest:replay` принимает завершённые годы через `--year`;
   готовой команды для произвольного отрезка 2026 пока нет.
5. Перед полноценным прогоном: тесты отсутствия future leakage, точных
   границ сессий/баров, разрывов, нулевого/недостаточного объёма, округления
   лотов и цен, одновременно задетых стопа/тейка, gap-fill, стоимости,
   cash, ранжирования одновременных сигналов и детерминизма. Затем
   `npm run check` и `npm run build`.

Итог этого этапа — проверяемая гипотеза и зафиксированные условия её
опровержения. Положительный исторический тест сам по себе не разрешает
боевую торговлю; следующий безопасный этап — отдельная бумажная проверка.
